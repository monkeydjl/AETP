# Governance at the fixed execution boundary

M2-02 adds versioned Policy, snapshot-bound Approval, Decision lifecycle and human pause/resume/stop to the existing Command/Event chain. `GovernanceService` is a trusted host facility. Its Python object, store, execution service and input issuer must not be exposed to Agent code.

The first `project.governance.configure` requires an explicit host `owner_id` and the same authenticated actor. Later Policy versions require that owner. Subjects and roles are retained in Project facts; registered Agents cannot become humans, and human identities in any prior Policy remain reserved against later Agent registration. Roles express responsibilities, including independent review, rather than Agent rank or privileged communication routes.

Typical host flow:

1. Construct `GovernanceService(store, owner_id=..., execution=..., input_authority=..., clock=...)`. The optional execution service must use the same store; no default owner or implicit approval exists.
2. Configure a new Policy version with explicit subjects, action rules, TTL and renewal limits. Reusing a version or configuring CRITICAL auto/delegated approval is rejected.
3. Obtain `snapshot(project_id, target_type, target_id)` and submit `approval.request` with that target, exact action and arguments, TTL, and optional risk/expiry policy. The requester is also the executor.
4. Complete the required independent grant. A deterministic auto rule emits its own system grant; a delegation emits a separate delegated fact and requires the named delegate. MEDIUM permits a qualified peer or human; HIGH requires a human and CRITICAL the owner. Manual mode requires human approval for every supported action.
5. For a document, submit `tool.request` through `ExecutionService` with `approval_id` and the registered Session. For a Decision, submit `decision.approve` and `decision.activate`, each with the same approval and arguments. Admission and the actual write boundary both recheck current authorization.

Only `decision` and execution `task` target adapters are implemented. The other six valid target types reject `ENFORCEMENT_UNAVAILABLE`. Decision snapshots refer to the immutable proposal revision/digest; aggregate revisions still provide CAS for lifecycle commands. Task snapshots bind the current full execution record, operation, normalized content, Binding, epoch and Session. A changed target, parameter, actor, Policy or execution context needs a new approval.

Unknown inputs are untrusted. `InputAuthority.issue(command, exposure=..., sources=...)` is an ingress capability owned by a facility that can actually attest the input; copying a receipt, choosing the same source ID, or supplying a client trust flag cannot grant it. A valid new receipt cannot clear an existing Decision, source Action or Checkpoint context's untrusted provenance. Legacy document actions with no source record remain unknown. Pure Replay restores recorded provenance without reconstructing ingress capabilities.

`tick(project_id)` is an explicit host operation, with no background thread or notification sender. Consumption checks expiry even before tick. Governance TTL and veto windows freeze during Project pause, while Session credentials expire by wall time. Expiry atomically records escalation, rejection consequences, or a bounded new-ID renewal; exhausted/stale renewal requests escalate. Revocation retains impact and prior Action results. It cannot undo external effects.

Human Project pause/resume requires an Intervention ID, reason and impact. Pause closes dispatch but records each Binding as `unsupported` for proof of quiescence: the fixed Runtime cannot claim every execution is stationary. Existing messages, observations and tool reconciliation can continue. Resume queries recovery outside the writer transaction and rechecks durable facts/live Sessions inside it. Missing Sessions, unresolved Actions, incomplete Commands, stale approvals or invalid execution authority keep the barrier closed. A fresh Runtime never recreates a lost Session from Event JSON. Task stop revokes the Binding and preserves any IN_FLIGHT/UNKNOWN Action for reconciliation. Redirect/modify/override effects remain unavailable.

Every Command has one domain result. Compound operations use deterministic child Commands in one outer SQLite transaction. Each governance Event contains the pure, required `continuations`; Replay recomputes them, verifies child identity/actor/target/parameters/time/parent/order and verifies the host-tick root. A truncated compound may be inspected, but its parent stays pending for recovery until all descendants are present. Missing/rejected/out-of-order required children cannot be hidden by an unrelated command. Child rejection or append failure rolls the compound back; a typed rejection of the outer authenticated intent is retained when possible. Idempotent success never repeats children or reads a fresh clock.

Governed Projects currently rebuild their causal cursor from the complete fact stream because the older aggregate cache does not contain it. This favors verifiable recovery over cache throughput; it is not a general scalability claim. No Event Store schema migration is needed, and accepted M1/M2-01 histories retain their original meaning.

The executable example is `Docs/development/evidence/2026-09-12-m2-02-demo.py`; pass a new `m2-02-...` output name for each run. It preserves a prior M2-01 proposal, activates it after independent approval, writes real document files, refuses resume after Session loss, safely replaces the execution context, restores a Checkpoint, and records veto/expiry. Its facts-only database and every Event prefix are replayed with live facilities guarded against calls.

This is limited work-item evidence. Whole-M1 acceptance remains `not_accepted`, formal Verification remains `INCONCLUSIVE`, no legitimate Task COMPLETED is claimed, complete Conformance remains 28 registered/0 passed, and Bootstrap remains `not_started`. The document provider is bounded Windows filesystem enforcement; it does not provide a general OS sandbox, paid-model budget ledger or arbitrary external tool capabilities.
