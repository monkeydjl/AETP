## 行为与验收边界

- 同一 `(project, trusted actor, key)` 和完整不可变 Command 内容返回原结果；旧 key 搭配不同 ID、payload 或 correlation 视为内容冲突。
- 被拒绝的原结果同样持久保留；缺失、损坏或属于其他 Command 的结果 fail closed，不当作未命中新请求执行。
- lookup 位于既有 `BEGIN IMMEDIATE` 事务内，结果登记与 Command/Event 批次原子提交；版本冲突保留 expected/current revision。
- 两个进程各自连接同一 SQLite 文件，双方 ready 后统一放行；正确性由数据库事务保证，而非进程内锁。异常和超时只回收本次创建的子进程。
- release 后新 key 可重新 claim 并推进 revision 至 3；旧成功/拒绝结果保持原值，重试无新增 Event。
