## R1：SQLite 辅助路径保护

首次独立审查实际发现：旧 runner 只拒绝显式 DB/report/evidence 冲突，但 SQLite 会消费或删除隐式 `<db>-journal` / `<db>-wal`；报告落在 sidecar 路径也可能在后续 SQLite 打开时被删除。单独 `-shm` 原探针字节未变，不能误报它已被删除，但同样应预拒既存路径。

修正让 API 与 CLI 在任何输出写入前检查 DB、`-journal`、`-wal`、`-shm`、报告与证据目录；既存文件／目录／链接，以及任意相等或双向嵌套均拒绝，**不清理、不覆盖**。新测试核验既存字节不变且不创建新输出。dangling-link 用 `Path.is_symlink` predicate 模拟，以避免要求 Windows 创建链接权限；不是实际链接隔离验证，也不宣称抵御恶意宿主 TOCTOU。
