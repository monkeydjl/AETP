# M3-02 Task Quality Implementation Plan

> **For agentic workers:** Use executing-plans inline, with test-driven-development. Reuse `/root/m1_reviewer`; do not create another agent. Each completed candidate needs independent review.

**Goal:** Make fixed-document Task quality transitions and explicit no-integration completion executable without weakening frozen evidence or execution authority.

**Architecture:** TaskQualityService extends AcceptanceService. A separate pure quality evaluator, applicability module and causal cursor own the new versioned opt-in contract. Existing Runner and QA execution authorization remain independent.

**Tech Stack:** Python standard library, SQLite, Windows document Runtime and ResourceGate, unittest.

## 3. Rework, explicit completion and terminal protection

**Files:** new `src/aetp/quality/lifecycle.py`; tests `test_task_quality_lifecycle.py`; modify runtime/service.py and runtime/projection.py at terminal guards; collaboration/service.py comment M3-02-R1.
