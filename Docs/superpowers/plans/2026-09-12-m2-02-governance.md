# M2-02 Governance Implementation Plan

> **For agentic workers:** Use `executing-plans` in the main thread. Reuse only `/root/m1_reviewer` for independent review; no additional agents. Steps use checkboxes for tracking.

**Goal:** Implement auditable snapshot-bound approval, expiry/revocation paths and replayable human pause/resume at existing controlled execution boundaries.

**Architecture:** A governance service composes single-effect Commands inside a SQLite transaction. Pure reducers restore all approval/policy/control facts; live runtime gates recheck current authorization. The executor owns implementation; the existing reviewer independently verifies a fixed candidate.

**Tech Stack:** Existing Python standard library, SQLite, unittest, fixed Windows document Runtime.

**Spec:** `Docs/superpowers/specs/2026-09-12-m2-02-governance-design.md`

## Global constraints

- No ClaudeLink, new agents, Git init/commit/push, dependencies, networking or global configuration.
- Preserve accepted and failed historical artifacts; baseline sources have already been archived before product edits.
- No product State writes outside Command/Event projection. External calls stay outside database transactions.
- Approval is not a generic tool capability; unsupported target/action adapters reject.
- Done requires a different independent reviewer and recorded commands/exit codes.
- Preparation/full-protocol counters retain the values specified in the design.
