# M2-01 Structured Discussion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use executing-plans inline. User permits only one reused independent reviewer; the main agent implements all tasks and the reviewer reviews frozen evidence. No new subagents or Git operations.

**Goal:** Implement bounded local Discussion/Meeting lifecycles and immutable Decision proposals with preserved dissent.

**Architecture:** Separate process tables from authoritative Command/Event facts in the existing SQLite database. Persist only lifecycle/accounting checkpoints and formal proposal snapshots; pure reducers never call the process store or meter.

**Tech Stack:** Python standard library, SQLite, unittest; current trusted Windows local host.

**Spec:** `Docs/superpowers/specs/2026-09-12-m2-01-discussion-design.md`.

## Global Constraints

- User disabled ClaudeLink; reuse only `/root/m1_reviewer`.
- Command → Event Store → Projection; no direct authoritative State writes.
- Policy `m2-local-discussion-v1`; receipt purpose `process_admission`, unit `token`.
- No default meter, provider execution/billing, Approval/activation or full-M1 acceptance.
- Preserve frozen M1 evidence and archive source before any shared-source changes.
- No dependency installation, network, global configuration, Git init/commit/push.
- Paused projects keep accepting existing material in its current phase; only new starts/normal phase advances are blocked. Meeting round controls do not apply to Discussion and are rejected there.
- Fixed participants are the consensus denominator; historical dissent remains in the source. Proposal fields outside Contribution are not covered by the admission meter.
